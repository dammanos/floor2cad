# Floor2CAD Accuracy Roadmap

## Goal

Produce the most accurate possible structured floor-plan output from raster plans and export it cleanly to DXF.

Target entities:
- walls
- openings
- text labels
- dimensions
- furniture
- rooms / zones
- scale / units
- confidence metadata
- grouped semantic output similar to Matterport-style scene understanding

## Current reality

The current pipeline is still MVP-level:
- walls are generated by a placeholder heuristic
- OCR is available but not yet structured into positioned text entities
- openings, furniture, and dimensions are not detected yet
- scale is fixed at `1.0`

This means output quality is currently limited by missing computer-vision stages, not by DXF export.

## Recommended target architecture

### Phase 1 - Strong image preprocessing

Before any detection, normalize the input:
- convert to grayscale
- deskew the image
- denoise
- adaptive thresholding
- contrast normalization
- remove large background shading
- detect and suppress text before wall extraction when needed
- generate multiple masks:
  - dark-ink mask
  - binary line mask
  - edge mask
  - text mask

Recommended stack:
- `opencv4nodejs` or native OpenCV binding for Node
- keep `sharp` for image IO/resizing
- keep `tesseract.js` only as a baseline OCR step

### Phase 2 - Accurate wall extraction

For walls, edge-only detection is not enough by itself. A good wall pipeline should combine:

1. edge detection
   - Canny edges
   - Sobel gradients for directional support

2. line extraction
   - Probabilistic Hough Transform
   - line segment filtering by length, angle, and density

3. wall-region extraction
   - adaptive thresholding
   - morphology close/open
   - contour extraction
   - skeletonization

4. geometric cleanup
   - merge collinear segments
   - snap nearly parallel lines
   - orthogonalize near-90° corners
   - join broken wall fragments
   - estimate wall thickness from paired contours

5. wall graph building
   - create nodes at intersections
   - split walls at doors/openings
   - enforce topology consistency

Best practical rule:
- use edges to find candidates
- use binary masks/contours to confirm actual wall regions
- use graph optimization to clean the final geometry

### Phase 3 - Text and label extraction

Text should be extracted as structured positioned elements, not raw strings.

Needed steps:
- detect text regions first
- OCR region by region
- keep bounding box, angle, confidence
- classify text type:
  - room label
  - dimension text
  - note
  - furniture label
  - scale label

Recommended output per text entity:
- text
- x/y anchor
- bounding box
- rotation
- confidence
- semantic category

## Phase 4 - Dimension extraction and scale estimation

Dimensions are critical because they convert pixels into real units.

Needed steps:
- detect dimension lines and arrows/ticks
- associate nearby OCR text with those lines
- parse units and values
- infer scale from repeated consistent dimensions
- reject inconsistent readings
- compute global meters-per-pixel or millimeters-per-pixel

Recommended logic:
- if at least 3 dimension readings agree within tolerance, promote scale confidence
- otherwise keep geometry in image space and mark scale as uncertain

## Phase 5 - Opening detection

Openings should be found using both geometry and symbols.

Detect:
- doors
- windows
- sliding doors
- double doors

Methods:
- look for gaps in wall centerlines
- detect swing arcs for doors
- detect thin parallel window patterns on wall segments
- use template matching or lightweight object detection for symbols
- bind openings to parent wall segments

## Phase 6 - Furniture detection

Furniture is much harder than walls and text.

Recommended approach:
- start with contour/blob-based candidates for large symbols
- classify candidates by shape descriptors
- then move to a trained detector for common symbols

Suggested categories:
- bed
- sofa
- table
- sink
- toilet
- shower
- kitchen counter
- wardrobe
- stairs

Best stack for this phase:
- object detection model exported to ONNX
- run through `onnxruntime-node`
- fallback to contour heuristics for simple symbols

## Phase 7 - Room / zone inference

To approach Matterport-style semantics, infer rooms from wall topology.

Needed steps:
- build enclosed regions from wall graph
- assign room labels from nearby OCR text
- associate furniture with containing room
- expose room polygons, area, centroid, and name

Recommended room output:
- polygon
- area
- centroid
- room name
- confidence
- linked openings
- linked furniture

## Phase 8 - Matterport-like structured output

Matterport-like output usually implies more than just lines.
It implies a semantically structured scene.

Recommended entities to support:
- walls
- openings
- rooms
- furniture
- dimensions
- labels / text
- floor level
- scale / units
- confidence scores
- source-image metadata

Recommended future schema additions:
- `Room`
- `BoundingBox`
- `DetectionSource`
- `ExtractionMetrics`
- `FloorLevel`

## Best implementation order for this codebase

### Immediate next step
1. Replace `WallDetector` with a real wall pipeline using OpenCV.
2. Change OCR output from raw text to structured positioned text elements.
3. Add a `DimensionDetector` that combines OCR and line matching.
4. Add `Room` inference after wall graph generation.
5. Add furniture detection last.

### File-level implementation plan
- `src/server/services/ImageProcessor.ts`
  - add deskew
  - add adaptive thresholding
  - add morphology helpers
  - add text-region masking
- `src/server/services/detectors/WallDetector.ts`
  - replace placeholder logic with edge + contour + Hough pipeline
  - return merged and snapped wall graph
- `src/server/services/detectors/TextDetector.ts`
  - new file
  - return structured text boxes and OCR text
- `src/server/services/detectors/DimensionDetector.ts`
  - new file
  - detect dimension lines and parse values
- `src/server/services/detectors/OpeningDetector.ts`
  - new file
  - detect doors/windows and attach them to walls
- `src/server/services/detectors/FurnitureDetector.ts`
  - new file
  - start heuristic, later replace with ONNX model
- `src/server/services/FloorPlanConverter.ts`
  - orchestrate all detectors
  - estimate scale
  - infer rooms
  - attach confidence metadata
- `src/shared/types.ts`
  - add room and metadata types

## Quality strategy

Accuracy should be measured, not guessed.

Create a small benchmark set with 20-50 plans and annotate:
- wall centerlines
- wall thickness
- openings
- room labels
- dimensions
- furniture symbols

Track metrics:
- wall precision / recall
- junction accuracy
- IoU for room polygons
- OCR character accuracy
- dimension value accuracy
- furniture classification accuracy

## Practical recommendation

If the target is truly best possible output, the project should move from:
- `sharp + heuristics`

to:
- `OpenCV + OCR layout analysis + geometric graph cleanup + optional ONNX detection`

That is the shortest path to high-quality CAD-ready output.

## Recommendation for the next implementation cycle

Build these in order:
1. real wall detection
2. structured OCR text detection
3. dimension + scale extraction
4. opening detection
5. room inference
6. furniture detection

That order gives the biggest accuracy improvement earliest.
